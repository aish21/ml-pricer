# Phoenix surrogate v2

> Historical specification: v2 has been superseded by the payoff-aware v3
> development/audit pipeline. See
> [`phoenix-payoff-aware-v3.md`](phoenix-payoff-aware-v3.md). Existing v2
> artifacts intentionally fail the v3 runtime contract and remain unserved.

`phoenix-surrogate-mlp-v2` is a product-focused research surrogate for
`phoenix-single-v1` under `equity-gbm-piecewise-v1`. It is underlier-generic:
the numerical inputs are normalized spot, product terms, and market curves, so
the model is not tied to SPY or any other ticker. It is product-specific because
different payoff contracts have different discontinuities and cashflow rules.

The surrogate is shadow-only. The Monte Carlo reference remains the returned
price, even when a surrogate artifact is loaded successfully.

## Versioned contract

The v2 feature vector contains 22 values:

- current spot divided by the frozen contractual reference spot;
- log spot distance to the autocall, coupon, and knock-in barriers;
- maturity, autocall barrier, coupon barrier, coupon per observation,
  knock-in barrier, and observation count;
- average continuously compounded zero rate, average dividend yield, and total
  variance at 25%, 50%, 75%, and 100% of maturity.

The contractual reference spot is distinct from current market spot. This keeps
barriers fixed when spot is shocked and lets the same schema represent seasoned
or scenario-valued trades. Curves must cover maturity and all inputs must fall
inside the training domain recorded in the artifact manifest.

The relevant identifiers are:

- feature schema: `phoenix-surrogate-features-v2`;
- label schema: `phoenix-piecewise-sobol-label-v1`;
- model: `phoenix-surrogate-mlp-v2`;
- artifact schema: `phoenix-surrogate-artifact-v1`.

Any contract, feature, market-model, or label change requires a new version.

## Dataset and leakage controls

The default dataset has 1,024 independently sampled Phoenix contract groups and
four market regimes per contract, for 4,096 cases. Contract groups—not rows—are
assigned deterministically to train, validation, and untouched test splits.
This prevents the same product terms appearing on both sides of a split under a
different market regime.

Labels are generated by the piecewise Monte Carlo reference with 252 time steps.
Each case uses two independent scrambled Sobol replications of 1,024 paths. The
dataset stores the label standard error and payoff dispersion alongside the
price. Its fingerprint covers configuration, contract metadata, features,
labels, uncertainties, group assignments, splits, and regimes. Dataset files
are compressed NumPy archives loaded with pickle disabled. Python, NumPy, and
SciPy generation versions are included in both metadata and the fingerprint.

## Training and acceptance

Training fits a standardized two-layer scikit-learn MLP and exports only its
numeric arrays for pure-NumPy inference. A LightGBM model is evaluated as a
research baseline but is never runtime-eligible. The API image therefore does
not require scikit-learn or LightGBM.

Metrics are reported separately for train, validation, and untouched test data.
The default shadow-approval gates are:

- test MAE no greater than `0.02` per unit notional;
- test 95th-percentile absolute error no greater than `0.05`;
- test R-squared at least `0.90`;
- no individual test market regime with MAE above `0.03`;
- at least 40% of test predictions within two estimated label standard errors;
- Delta, Vega, and Rho sign agreement of at least 50% on the offline paired-path
  Greek checks across 16 cases with 4,096 common-random-number paths each.

Artifacts that miss any gate are labelled `research_only`. The pipeline still
records them for diagnosis, but the service rejects them unless a local
research override is explicitly enabled. Acceptance thresholds must not be
relaxed merely to promote a particular training run.

## Running the pipeline

Install training dependencies and run the default end-to-end job:

```powershell
python -m pip install -e ".[training,test]"
python -m src.final.surrogate_pipeline full
```

Generate once and train again from an immutable dataset:

```powershell
python -m src.final.surrogate_pipeline generate
python -m src.final.surrogate_pipeline train data/surrogates/phoenix-v2/datasets/<dataset-id>.npz
```

Generated datasets, manifests, logs, and weights live below
`data/surrogates/phoenix-v2/` and are excluded from Git. Every artifact is stored
in a content-addressed directory. `artifacts/current.json` is replaced
atomically after training. The manifest records dataset/configuration identity,
random seeds, training-library versions, split and regime metrics, Greek checks,
acceptance decisions, and the weights checksum.

## Shadow runtime

Shadow inference is disabled by default. To enable an approved local artifact:

```powershell
$env:PHOENIX_SURROGATE_SHADOW_ENABLED="true"
$env:PHOENIX_SURROGATE_DIR="data/surrogates/phoenix-v2/artifacts"
```

For deliberate local analysis of a failed artifact only:

```powershell
$env:PHOENIX_SURROGATE_ALLOW_UNAPPROVED="true"
```

Do not use that override in a deployed environment. The loader enforces exact
schema versions and feature order, approval status, path confinement, manifest
and weights size limits, SHA-256 integrity, finite array shapes, and a bounded
cache. Runtime outputs are domain-checked and sanity-bounded. Any shadow error
is isolated from reference pricing, and `used_for_price` remains false.

## Current boundary

This is still research infrastructure. It does not include a volatility
surface, credit or funding adjustments, irregular schedules, seasoned trade
state beyond a reference-spot ratio, or licensed market data. Shadow comparison
against a materially larger and more representative out-of-sample dataset is
required before considering any pricing-role change.
